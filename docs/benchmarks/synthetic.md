|---|---|

| Status | ready |

| Headline | `reproduction_skill` (0 to 1); reference: static scene 0 |
| License | Apache-2.0 (generated by Real2SimLab) |

Five phenomena generated by Real2SimLab with exact truth: analytic solutions or high-precision
integration, never a method's code. They are the suite to start with: small (CPU, seconds per
run), license-free, and noise-free, so every error is the method's.

| Task | What happens |
|---|---|
| `bouncing_ball` | a ball dropped onto a floor bounces until it settles |
| `pendulum` | a damped pendulum swings from a moderate angle |
| `incline_slider` | a block slides down an incline with friction and continues on the floor |
| `projectile` | a ball is thrown, with air drag |
| `two_ball_collision` | two balls of equal mass collide |

Each comes in two visibility tiers:

- **`calibrated`**: the video, the calibrated camera, metric scale, the scene's objects (sizes,
  initial poses, masses where relevant) and a text description;
- **`video_only`**: the video and the text only; the program must recover scale from what it
  sees. Its reproduction skill comes from the error in the image (`traj2d_norm_mean`, the mean
  2D error over the image diagonal); 3D errors are reported after a similarity alignment.

The hidden parameters (restitution, damping, friction, drag, ...) are deliberately not round
numbers, so a method cannot guess them; the reference, the generator and `parameters.json`
(the hidden parameters and the initial state) are under `hidden/` and never mounted into an
agent's workspace or a twin's run.

```bash
r2s bench build synthetic --out tasks/ --overwrite    # tasks/ may hold the quickstart's already
r2s eval --tasks tasks/ --method oracle --method static --method constant_velocity --out runs/synthetic
```

`oracle` is the generator itself (reproduction skill 1), `static` nothing moving (skill 0 by
construction) and `constant_velocity` each object's initial velocity extrapolated in a straight
line. `r2s bench build` never writes over a task unless given `--overwrite`, which builds it
again. Without Docker, add `--backend bwrap` to `r2s eval`
([Run on a cluster without Docker](../tutorials/clusters.md)).

**Fidelity**: the generator re-run as a frozen twin reproduces the reference exactly (skill 1,
tested); every task validates with no warnings.

**Training tasks**: `r2s train tasks` writes the same phenomena with their hidden parameters and
initial states sampled around these values, as `synthetic-train/...` tasks with
`split = "train"`, never a near copy of an evaluation task. A sample whose video the overlap
check cannot tell from the evaluation task's (two pendulums released a few degrees apart look
alike in a 32 × 32 thumbnail) is skipped, and the command says how many were. See
[Training](../guides/training.md).
